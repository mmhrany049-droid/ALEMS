# ۷. راهنمای UI/UX — نسخه ۱

## ۷.۱ اصول کلی

- **زبان پیش‌فرض:** فارسی
- **جهت:** RTL کامل
- **فونت اصلی:** وزیرمتن (Vazirmatn)
- **تقویم:** شمسی (جلالی)
- **هفته:** شنبه تا جمعه
- **تم:** روشن (پیش‌فرض) + پشتیبانی از تاریک در آینده نزدیک

---

## ۷.۲ صفحه اصلی پیشنهادی: Today Hub

صفحه اول برنامه باید پاسخ این سوال را بدهد:  
**«امروز چه کارهایی باید انجام دهم؟»**

محتوای پیشنهادی Today Hub:

1. وضعیت انرژی و حال (Daily Check-in سریع)
2. برنامه امروز (از ماژول Planning)
3. صف مرور ضروری
4. آزمون‌های نزدیک
5. خلاصه عملکرد ۷ روز اخیر (کوچک)
6. دسترسی سریع به ثبت تست و مطالعه

---

## ۷.۳ ناوبری اصلی (Bottom یا Side)

پیشنهاد منوی اصلی نسخه ۱:

| بخش | توضیح |
|-----|-------|
| امروز | Today Hub |
| مطالعه | ثبت فعالیت و مشاهده منابع |
| تست‌ها | ثبت تست + دفترچه خطا |
| مرور | صف مرور |
| برنامه | اهداف و برنامه هفتگی |
| آزمون | مدیریت و شبیه‌سازی آزمون |
| تحلیل | نمودارها و آمار |
| تنظیمات | پروفایل، Backup، تنظیمات |

---

## ۷.۴ الگوهای تعاملی مهم

### ثبت سریع تست
- کاربر باید بتواند در کمتر از ۳ کلیک نتیجه یک سوال را ثبت کند.
- امکان ثبت دسته‌ای (چند سوال پشت سر هم).

### علامت‌گذاری
- تیک‌ها به صورت دکمه/چیپ قابل روشن و خاموش شدن باشند.
- رنگ‌بندی ثابت و معنادار داشته باشند.

### صف مرور
- اولویت‌بندی واضح (بالا به پایین).
- امکان «الان مرور می‌کنم» و «بعداً».

### برنامه هفتگی
- نمای هفته (شنبه تا جمعه).
- امکان drag یا ویرایش ساده آیتم‌ها.

## ۷.۵ رنگ‌بندی پیشنهادی (نسخه ۱)

| مفهوم | رنگ پیشنهادی |
|-------|--------------|
| درست | سبز |
| غلط | قرمز |
| نزده | خاکستری |
| مهم | نارنجی / کهربایی |
| سخت | بنفش |
| مرور | آبی |
| انرژی بالا | سبز روشن |
| انرژی پایین | قرمز ملایم |

از کنتراست بالا برای متن اصلی استفاده شود.

---

## ۷.۶ تایپوگرافی

- عنوان‌ها: وزیرمتن Bold
- متن اصلی: وزیرمتن Regular
- اعداد و درصدها: واضح و درشت در کارت‌های آماری
- حداقل اندازه متن قابل خواندن روی موبایل رعایت شود

---

## ۷.۷ واکنش‌گرایی

- اولویت اول: دسکتاپ و لپ‌تاپ (چون مطالعه جدی معمولاً پشت میز انجام می‌شود)
- اولویت دوم: تبلت
- موبایل: قابل استفاده برای ثبت سریع و مشاهده Today Hub

---

## ۷.۸ حالت‌های خالی (Empty States)

هر صفحه باید پیام و دکمه مناسب داشته باشد وقتی داده وجود ندارد.  
مثال: «هنوز هیچ تستی ثبت نکرده‌ای — اولین تست را ثبت کن»

---

## ۷.۹ بازخورد کاربر

- تمام عملیات موفق باید بازخورد واضح داشته باشند (toast یا پیام کوتاه).
- خطاها باید به زبان فارسی و قابل‌فهم باشند.
- عملیات مخرب (حذف، Restore) نیاز به تأیید دومرحله‌ای دارند.

---

## ۷.۱۰ دسترسی‌پذیری پایه

- کنتراست کافی
- اندازه کلیک‌پذیر مناسب
- پشتیبانی از صفحه‌کلید برای عملیات اصلی (در دسکتاپ)
- عدم وابستگی صرف به رنگ برای انتقال معنا
