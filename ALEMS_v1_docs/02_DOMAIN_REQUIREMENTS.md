# ۲. نیازمندی‌های دامنه (Domain Requirements) — نسخه ۱

## ۲.۱ مفاهیم اصلی دامنه

| مفهوم | تعریف |
|-------|--------|
| **دانش‌آموز** | کاربر اصلی سیستم که مطالعه و تست ثبت می‌کند |
| **رشته** | ریاضی، تجربی، انسانی |
| **پایه** | دهم، یازدهم، دوازدهم، فارغ‌التحصیل |
| **درس** | مثلاً حسابان، فیزیک، شیمی، زیست |
| **فصل / مبحث / زیرمبحث** | سلسله‌مراتب محتوا |
| **منبع (Resource)** | کتاب تست، کتاب درسی، جزوه، ویدئو، کلاس |
| **سوال** | یک تست با پاسخ و متادیتا |
| **فعالیت** | مطالعه، تست‌زنی، مرور، کلاس، مدرسه |
| **رکورد تست** | نتیجه حل یک سوال (درست/غلط/نزده) |
| **دفترچه خطا** | ثبت نوع اشتباه برای هر غلط |
| **مرور** | بازبینی سوالات علامت‌خورده یا غلط |
| **آزمون** | مجموعه سوالات با زمان و نمره‌دهی |
| **هدف** | هدف بلندمدت، ماهانه یا هفتگی |
| **برنامه** | تخصیص زمان و محتوا به روز/هفته |

---

## ۲.۲ نیازمندی‌های عملکردی اصلی

### FR-01: مدیریت هویت
- ساخت پروفایل دانش‌آموز با نام، پایه، رشته، سال تحصیلی و هدف کنکور
- ورود با نام کاربری و رمز عبور
- پشتیبانی از چند پروفایل روی یک دستگاه

### FR-02: ساختار دانش
- تعریف درخت دروس بر اساس رشته و پایه
- وارد کردن کتاب تست از فایل JSON استاندارد
- ذخیره سوالات با مبحث، پاسخ، سطح سختی و تگ‌ها

### FR-03: ثبت فعالیت
- ثبت جلسه مطالعه (درس، مدت زمان، منبع)
- ثبت نتیجه تست (درست / غلط / نزده + زمان حل اختیاری)
- علامت‌گذاری سوال (مهم، مرور، سخت، اشتباه، نکته‌دار)

### FR-04: دفترچه خطا و مرور
- ثبت نوع اشتباه برای هر غلط (بلد نبودن، فراموشی، بی‌دقتی، کمبود زمان)
- تولید صف مرور بر اساس غلط‌ها، نزده‌ها و تیک‌های مهم/سخت
- امکان علامت‌گذاری «مرور شد»

### FR-05: برنامه‌ریزی
- تعریف اهداف بلندمدت، ماهانه و هفتگی
- ثبت زمان‌های ثابت (مدرسه، کلاس)
- تولید و ویرایش برنامه روزانه و هفتگی

### FR-06: آزمون و نمره‌دهی
- ایجاد آزمون آزمایشی (چند درس) یا امتحان (یک درس)
- محاسبه درصد با نمره منفی (فرمول کنکور) و بدون غلط
- تحلیل عملکرد بر اساس سطح سختی

### FR-07: تحلیل و گزارش
- آمار عملکرد به تفکیک درس، فصل، مبحث
- نمودارهای پایه (خطی، میله‌ای، دایره‌ای)
- گزارش روزانه، هفتگی و ماهانه
- خروجی PDF، Excel و JSON

### FR-08: پشتیبان‌گیری
- Backup دستی و خودکار
- Restore کامل
- انتقال داده بین دستگاه‌ها از طریق فایل

## ۲.۳ نیازمندی‌های غیرعملکردی

| کد | نیازمندی | توضیح |
|----|----------|-------|
| NFR-01 | Offline-First | تمام قابلیت‌های اصلی بدون اینترنت کار کند |
| NFR-02 | عملکرد | ثبت تست باید کمتر از ۲۰۰ میلی‌ثانیه طول بکشد |
| NFR-03 | قابلیت نگهداری | معماری ماژولار با مرزهای واضح |
| NFR-04 | امنیت داده | رمز عبور هش‌شده، Backup قابل رمزنگاری |
| NFR-05 | دسترسی‌پذیری | پشتیبانی کامل RTL و فونت فارسی خوانا |
| NFR-06 | قابلیت انتقال | خروجی کامل داده‌ها در فرمت باز (JSON) |
| NFR-07 | تقویم | پشتیبانی کامل از تقویم شمسی و هفته ایرانی |

## ۲.۴ قوانین دامنه کلیدی

1. **درصد کنکوری**:  
   `(تعداد درست - ۰.۳۳ × تعداد غلط) / تعداد کل سوالات × ۱۰۰`

2. **درصد بدون غلط**:  
   `تعداد درست / تعداد کل سوالات × ۱۰۰`

3. **هفته ایرانی**: شنبه تا جمعه

4. **سطح سختی پیش‌فرض**: آسان / متوسط / سخت (قابل تغییر توسط کاربر)

5. **یک سوال می‌تواند چندین تیک همزمان داشته باشد**

6. **مرور فقط روی سوالاتی که هنوز «مرور شد» نشده‌اند انجام می‌شود**

7. **هر رکورد تست متعلق به یک منبع و یک مبحث است**

## ۲.۵ سناریوهای اصلی کاربر (User Stories خلاصه)

- به‌عنوان دانش‌آموز می‌خواهم کتاب تست وارد کنم تا بتوانم تست‌هایش را ثبت کنم.
- به‌عنوان دانش‌آموز می‌خواهم بعد از حل تست، نتیجه و نوع اشتباه را ثبت کنم.
- به‌عنوان دانش‌آموز می‌خواهم سیستم به‌صورت خودکار لیست مرور روزانه‌ام را بسازد.
- به‌عنوان دانش‌آموز می‌خواهم برنامه هفتگی‌ام را ببینم و تغییر دهم.
- به‌عنوان دانش‌آموز می‌خواهم بعد از یک آزمون آزمایشی، درصد و تحلیل عملکردم را ببینم.
- به‌عنوان دانش‌آموز می‌خواهم گزارش هفتگی‌ام را به PDF خروجی بگیرم.
- به‌عنوان دانش‌آموز می‌خواهم از تمام داده‌هایم Backup بگیرم.
